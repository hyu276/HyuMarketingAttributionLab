# Product Design System: The Attribution Workbench

**Mode:** Operate. **Personality:** calm, rigorous, analytical. **Priority:** provenance, clarity and productive comparison ahead of ornamental novelty.

## Design intent

A user should first notice the current measurement context (model, lookback, data status), then one meaningful attribution comparison, and then the pathway from touchpoint -> order -> attributed outcome. The recognizable design element is the **evidence trace**: timeline and allocation next to a plain-language explanation, not decorative SaaS cards.

## Tokens and information hierarchy (initial proposal)

- Canvas: warm off-white; text: graphite/navy ink; surfaces: white, flat, minimal borders; one teal/blue-green interaction accent.
- Semantic: amber for uncertainty, red for error, green for confirmed data; never use color without a textual label.
- Typography: clean sans for text, tabular numerals for data; hierarchy through scale and spacing, not heavy shadows.
- Space: clear reading rhythm and comfortable table density; no card-in-card stacks.
- Components: navigation, model select, lookback select, journey timeline, allocation result, source labels, method note, UTM tool and permission/empty states.
- Mobile: filters wrap/reflow, journey turns vertical, data grid scrolls with explicit context; no hiding provenance.

## Five-question review

1. Color: is the primary action or comparison the focal point?
2. Decoration: does every visual accent convey a status, source or affordance?
3. Layout: is content represented by the proper structure, especially timeline/table?
4. Coherence: do repeated states/tokens/components follow the same rules?
5. Copy: does every label accurately name the data, method and next action?
